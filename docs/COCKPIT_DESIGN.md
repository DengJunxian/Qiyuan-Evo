# Agent Evolution Cockpit

## Design contract

Visual thesis: a calm, dark research operations workspace, with a cyan accent and an actual agent topology as the visual anchor. No decorative image or simulated activity.

Content plan: compact identity and runtime provenance → configuration-derived requirement counts → one primary demo action → team graph and trace stream → measured evolution and comparison. Dedicated pages hold full collaboration, generation comparison, memory, task gallery, domain tools and reproducibility.

Interaction thesis: node hover reveals metadata; trace and prompt details expand on demand; a background job updates real execution observations without blocking navigation. No fabricated animation or artificial delays. Reduced-motion settings disable optional transitions.

## Navigation

1. 自演进驾驶舱: concise competition story, current team, real demo action, latest comparison.
2. 协作过程: run selection, trace replay, event evidence and tools.
3. 演进实验: measured timeline, before/after, generation comparison, experience reuse.
4. 三类任务: A/B/C baseline, evolved, comparison, trace and exact reproduction.
5. 金融政策风洞: existing business pages as domain skills/environments.
6. 历史验证: original historical workbench.
7. 技术与复现: actual SDK state, requirement matrix, source/data hashes and runnable commands.

## Provenance and reliability

- REPRODUCIBLE DEMO: frozen input, fixed seed, bounded financial simulation, real selected Workflow runtime; cloud optimizer disabled.
- ONLINE LIVE: same workflow, optional real cloud Prompt optimizer, explicit missing-key/error fallback.
- OFFLINE FALLBACK: explicit local graph backend and deterministic optimization.
- Loaded artifacts are labelled completed experiments with source revision, runtime, seed and run IDs. They are never called live.
- Every new one-click demo gets an isolated experience directory so the same baseline-to-candidate process is visible without deleting history. Repeated task experiments can reuse that directory.
- Runtime observers are passive. Their failure cannot change financial computation, score or workflow control.
- Empty, invalid or incompatible artifact states do not synthesize results. Exact rerun checks source identity.
- Only real configuration generations are displayed; version aliases and unimplemented retire/merge transitions are not invented.

## Acceptance

Test profiles, paired-condition validation, artifact failure states, passive observers, runtime states, actual memory references, metric direction, all seven pages, original domain pages and background-job failure recovery. Run native openJiuwen demo and complete benchmark; open major pages in a browser and inspect logs.
